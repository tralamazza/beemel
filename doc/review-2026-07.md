# BML Systematic Review -- 2026-07

Scope: soundness/correctness audit of `bml-core` + claims-vs-implementation
check against `doc/` and `paper/`. Method: per-subsystem falsification with
empirical `.bml` probes where a candidate hole exists. Deliverable is this report
plus the severity-sorted backlog at the end.

A "finding" is either (a) the compiler accepts a program that violates an
invariant it claims to enforce (soundness), or (b) a doc/paper claim that the
code does not back. Findings are classed `S` (soundness/miscompile), `F`
(false-negative), `P` (false-positive), `C` (claim/doc discrepancy), `T`
(test/CI gap), `H` (latent hardening / robustness).

## Summary

Ten subsystem passes + two cross-cutting sweeps. No **Critical, hidden**
soundness hole was found: the core safety machinery (E347/qualify foundation,
context isolation, ceiling/priority model, preemption havoc, nsw/V130 modeling,
match static-exhaustiveness, comptime limits) held up under falsification, and the
paper's §7 evaluation claims reproduce exactly. The findings are one confirmed
*disclosed* miscompile (F2), one codegen bug that fails loudly (S1), one
false-exhaustiveness gap (F1), and a cluster of test/CI and metadata gaps.

## Fixes applied (2026-07)

All findings except the two remaining hardening items were fixed in the same
pass; the full suite (646 unit/integration + 63 exec/QEMU + verify/IKOS) stays
green, fmt/clippy clean.

- **F2 NARROWED (not fully closed)** -- `region.rs` now tracks agent-address
  provenance in one `classify(e) -> {Ptr, AddrInt, None}` pass (the public
  `is_agent_ptr_expr` is a thin view). An integer carrying an agent-static
  address (`&X as u32`, propagated through `+`/`-`, casts, and `+=`) round-trips
  back to a tracked `Ptr` at `int as *T`, so an *intra-function* laundered
  pointer lowers `volatile` again. `Ptr` and `AddrInt` are the same address with
  different consequences (deref/escape vs. delivery), so no form is special-cased
  -- `(base+off) as *T`, `(&X+off) as *T`, `+=` accumulation, and ptr->int->ptr
  round-trips are all covered by construction. E620 keys on `Ptr` only, so the
  `&BUF as u32` delivery idiom is untouched. Verified: `/tmp/rp/laundered.bml`
  and `/tmp/rp/compound.bml` at `-O2` both go to 9 volatiles with the poll
  reloading inside the loop. Regression tests:
  `test_agent_ptr_laundered_volatile_lowering` (+`_compound`) + fixtures
  `agent_ptr_laundered.bml`, `agent_ptr_laundered_compound.bml`. Covers the
  observed H723 §7.3 pattern (in-function OWN-bit poll).
  **Residual, still open (self-review):** the taint is per-function, so passing
  the address as a `u32` argument into a callee that reconstructs and
  dereferences it (`fn poll(a: u32){ var p = a as *u32; ... p[3] ... }`,
  `poll(&DESC as u32)`) is still non-volatile and still hoists at `-O2`

  reject it without breaking legitimate integer delivery (a delivery helper

  inter-procedural taint -- the paper's disclosed limitation. So F2 is "the
  common case closed; cross-function integer delivery-then-deref remains a
  documented limitation." The `language.md`/`regions-agents.md` disclosure holds.
  The exponential-recursion risk the self-review raised for the earlier two-
  predicate form was refuted (polarity short-circuit -> linear) and is now moot:
  the single `classify` pass visits each node once.
- **S1 fixed** -- `expr_type(Expr::Match)` (`ir.rs`) now returns the first
  non-diverging arm's trailing-value type. Regression: exec fixture

- **F1 fixed (documented)** -- `doc/language.md` enum Semantics now states that

- **C2 fixed** -- README/REVIEW page count reconciled to the actual 9 pages.
- **T1 addressed** -- CI now installs `qemu-system-arm` + `gcc-arm-none-eabi`, so

## Pass 1 -- Front-end integrity (lexer/parser/resolver/imports/qualify)

**E347 no-shadowing (qualify.rs's load-bearing foundation): SOUND.**
`check_shadowing` (`checker.rs:193`) seeds the outermost scope with module value
names (functions, statics, consts, peripherals -- `checker.rs:198-202`) and nests
params + block/for scopes below it. The only binding forms in the language are fn
params, `var`/`const` decls, and the for-loop variable; all three route through
`shadow_declare`. Match patterns bind no names (`MatchPattern` = Variant/Int/
Range/Wildcard, `ast.rs:827`) and `claim` names an existing static, so no binding
form is missed. Empirically confirmed: a local shadowing a global `const` and a
nested-block shadow both raise E347 (`/tmp/bml_shadow_probe.bml`). Types live in a
separate namespace and are intentionally not seeded, which is safe because
qualify rewrites value-position references (bare) and type-position references use
distinct syntax (`T { .. }`, `T@V`). No finding.

**E113 parser depth guard (fuzzer's stack-overflow protection): SOUND.**
All recursion bottoms out through `guarded()` (`parser.rs:183`) at exactly the
three mutually-recursive nonterminals -- `parse_expr_prec` (`:1933`),
`parse_type_expr` (`:1436`), `parse_block` (`:1543`). Statements recurse only via
guarded blocks/exprs; patterns and items are non-recursive. Matches the E113
message "(expression, type, or block)". The no-panic fuzzer passes. No finding.

**H1 (Low) -- `push_unique` silently drops items on span collision.**
`imports.rs:297` dedups merged top-level items by their defining-name `Span`. The
header itself documents two silent-drop cases: importing the same file under two
aliases (only the first qualification survives), and -- per project memory -- any
future desugar/synthesis pass that emits multiple top-level items sharing a span
will have all but the first silently dropped. This violates "fail loudly": a span
collision among *distinct* synthesized items should be an internal error, not a
silent drop. Not user-reachable into a miscompile today (same-file aliases are
semantically identical; unresolved refs fail loud), so Low. Fix: assert-or-error
on span collision between non-identical items, or key dedup on (span, item-kind,
content-hash). Effort: S.

## Pass 2 -- Type checker & moves (checker.rs, types.rs)

**Match exhaustiveness: SOUND at the checker level.** `check_match_coverage`
(`checker.rs:1710`) requires an enum match to cover every declared variant or
carry `_`, and requires *every* integer match to carry `_` (the value space can't
be enumerated). Duplicate/out-of-range/empty-range patterns are rejected
(E319/E344). No finding on the static check itself. But see F1.

**S1 (Medium, codegen) -- match-*expression* result phi is mis-typed; the
compiler emits invalid IR for a well-typed program.**
`IrEmitter::expr_type(Expr::Match)` (`ir.rs:6010-6017`) returns the enum's *inner*
type for an enum scrutinee, and a hardcoded `U32` otherwise -- **not** the arm
result type. But the match arms emit values of their real result type, and the
phi/default block are typed from `expr_type`. When the arm type's LLVM width
differs from that, the `phi` is malformed and `llc` rejects the module. This
directly contradicts the emitter's own comment at `ir.rs:3996-3998` ("The phi is
over the arm *result* type ... not the scrutinee type"). The checker types the
match correctly -- `var r: u8 = <enum match with u32 arms>` is rejected E300
"declared U8 but initialized with U32" -- so this is purely an IR/checker type
disagreement.
- Repro (no cast needed), accepted by `bml check`, rejected by `llc`:
  - enum: `/tmp/enum_match_expr.bml` -- `enum Color: u8`, `var r: u32 = match c {
    Color@Red {100} Color@Green {200} Color@Blue {300} }` ->
    `phi i8 ... '%3' defined with type 'i32' but expected 'i8'`.
  - integer: `/tmp/int_match_u64b.bml` -- `var r: u64 = match x { 1 {a} 2 {b} _ {c} }`
    with u64 arms -> `phi i32 ... '%4' defined with type 'i64' but expected 'i32'`.
- Not a silent miscompile: the phi disagreement is always caught by `llc`
  (loud), and the only cases that slip through are small literals that fit the
  narrow type anyway (no data loss). But it is a valid program the compiler
  cannot build, and the failure surfaces as a raw internal IR dump.
- Fix: make `expr_type(Expr::Match)` return the trailing-value type of a
  non-diverging arm (mirror the `Expr::Block`/`Expr::If` arms just below it,
  which use `self.expr_type(trailing)`). Effort: S. Add an exec/build-validity
  fixture -- the build-validity fuzzer covers scalars only, not match arms.

**F1 (Medium) -- "exhaustive match" does not hold for enums, because int->enum
casts (documented) and hardware reads produce undeclared discriminants.**
`doc/language.md:935` documents `var back: State = raw as State;` as an intended
feature (round-trip through an integer, the hardware-register-decode use case).
`x as Enum` is accepted for any integer -- `200 as Color` with variants {0,1,2} is
accepted (`/tmp/enum_fab.bml`). So an enum value can hold a discriminant no
variant names. But `check_match_coverage` treats a wildcard-free enum match that
covers all *declared* variants as exhaustive, and the IR switch's default for a
statement match is `end_lbl` (silent no-op) / for an expression match is a dummy
`add <ty> 0,0` (yields 0). Result: a programmer who writes a wildcard-free match
over every named variant of a status register decoded via `as` believes every
value is handled; a reserved/invalid hardware value silently falls through to a
no-op or 0. This is the exact "silent fall-through" the language warns about for
AST walkers, surfacing at the user level. Not memory-unsafe (default is defined).
- Fix options: require a `_` arm for any enum match whose scrutinee is not
  provably constructor-only; or document the caveat and define a trap/`assert`
  for the undeclared-discriminant default. Effort: M. Cross-check with the
  language spec's "match is exhaustive" wording.

**H2 (Low) -- forged `ErrorGuaranteed` on "checker should have caught this"
paths.** `expr_type` constructs `Type::Error(unchecked_claim_error_was_emitted())`
at `ir.rs:5979` and `:5989` (unknown struct / enum) and `checker.rs:3786`, on the
assumption the checker already erred. The `ErrorGuaranteed` witness (`errors.rs:11`)
exists precisely to prevent `Type::Error` without a real diagnostic; these three
sites forge it. Benign while the checker has no holes upstream, but they erode the
witness invariant -- if a checker gap ever lets one of these paths run in a
zero-error compile, a forged error type flows into codegen silently. Low. Fix:
route through the actual diagnostic, or `debug_assert!(diags.has_errors())`.

## Pass 3 -- Borrow / storage-class / context (borrow.rs, context.rs)

**Context isolation: SOUND.** Empirically:
- E403 rejects an ISR directly calling a `@context(thread)` fn (`/tmp/ctx2.bml`).
- E408 rejects taking the *address* of a context-restricted fn
  (`/tmp/ctx3.bml`), so an ISR cannot launder a thread-only call through a
  function pointer -- the restriction is enforced at the address-of site, before
  a pointer even exists, which is stronger than checking at the indirect call.
- The unannotated-helper laundering hole is closed by propagation: an `Any`-context
  helper called from an ISR is checked in ISR context via `fn_possible_contexts`
  (`borrow.rs:361-377`).
No finding.

## Pass 10 -- AST-walker exhaustiveness sweep (cross-cutting)

**Convention holds for the primary dispatchers.** `ceiling.rs` has zero `_ =>`
arms (matching its "exhaustive walkers, no catch-all" header). The 198 catch-alls
elsewhere are in value classifiers, const folders, sub-matches on non-AST enums
(BinaryOp/Type/StorageAnnotation/TokenKind), and a recurring `else`-branch
sub-handler pattern (`borrow.rs:89`, `verify/preempt.rs:248`, `stack.rs:344`) that
matches an if/else chain's else Stmt and `_ => {}`s the non-If/Block cases. The
primary `Stmt`/`Expr`/`LValue` structural dispatchers (emit_stmt, check_expr,
scan_stmt, walk_stmt, ...) remain exhaustive. No soundness finding.

**Obs (very low)**: the `else`-branch `_ => {}` handlers rely on the parser
constraining `else` to If/Block; if a future Stmt could appear as an else-branch
it would be silently skipped by borrow/preempt/stack. Defensive dead code today.

## Pass 5 -- Region / agent ownership (region.rs, target.rs)

**F2 (High; impact Critical, but DISCLOSED) -- integer-laundering an agent-static
address defeats the volatile taint -> silent MMIO-poll miscompile.**
CONFIRMED reproduction of the limitation documented at `regions-agents.md:469-494`
and paper §9. `is_agent_ptr_expr` (`region.rs:2935`) only follows *pointer-typed*
casts; `&X as u32` deliberately exits the taint (the handoff-delivery idiom), and
integer arithmetic on that value stays untainted (`_ => false`). A pointer
reconstructed via `(&X as u32 + off) as *T` is therefore not lowered `volatile`,
and E620 does not fire on it.
- Empirical, target `reclaim_guard.target`, region `pool` + DMA agent, at `-O2`:
  - direct `&DESC as *u32` (`/tmp/rp/direct.bml`): 9 volatile ops; the OWN-bit
    spin is `load volatile ... inside the loop` -- polls correctly.
  - laundered `(&DESC as u32 + 0) as *u32` (`/tmp/rp/laundered.bml`): 3 volatile
    ops (only the reset `.data` copy); the poll load is **hoisted out of the
    loop** (`%.pr = load i32 ...`, non-volatile) and the body degenerates to
    `while_cond.0: br label %while_cond.0` -- an infinite `b .`. This is exactly
    the H723 hang the rule was created to prevent (§7.3), reproduced through the
    escape.
- Not a claims discrepancy: the paper and docs disclose it accurately, so this
  is a *confirmed, still-live* disclosed limitation, ranked High because the
  trigger -- integer arithmetic on a hardware address -- is idiomatic embedded
  code, and the failure is a silent hang with no diagnostic.
- Fix direction: propagate taint through the *integer* derived from an
  agent-static address and re-taint at `int as *T`, so only pure delivery
  (integer written to a handoff register, never cast back and dereferenced)
  exits; or have E620 reject an `int as *T` whose integer operand is
  provenance-tainted. Effort: M. Cross-check against the handoff-delivery idiom
  so `&BUF as u32` written to a register still passes.

Otherwise the region model's pointer-escape coverage is sound: E620 + the
fixtures `agent_ptr_escape_{arg,return,asm}` cover the direct-pointer escape
routes; only the integer-laundering path (F2) escapes, as documented.

## Pass 8 -- Verify / IKOS boundary (verify/*)

**Preemption-havoc model: SOUND.** The self-preemption exclusion is correct and a
reader is *not* wrongly exempted just for being a writer (`preempt.rs:29-36`). My
concern that `Context::Any => 255` under-rates an `Any` writer's urgency is
resolved by the transitive write-set closure (`compute_writers`, `preempt.rs:112-129`):
a `@shared` write inside an `Any` helper called from a prio-1 ISR makes that ISR a
writer at prio 1, so a mid-priority reader is correctly havoc'd. `Any => 255` is
therefore safe for writers (propagation supplies the real priority) and
conservative for readers. Fn-pointer indirection is over-approximated (all `Any`
fns are possible callees). No finding.

**V130 signed-overflow escalation: SOUND and confirmed.** Plain `a + b` on
unconstrained i32 raises V130 signed overflow *and* underflow, both escalated to
error; `a +% b` is suppressed (`/tmp/ovf.bml`). This gate is what makes the
`nsw`-only tagging + `--no-wrap-sign-only` modeling sound: the verifier may treat
plain ops as non-wrapping precisely because any program where they might wrap
fails the gate (`verify/mod.rs:254-263`). No finding.

## Pass 9 -- Target physics / startup (target.rs, arch/)

## Cross-cutting -- Claims vs. implementation + test/CI gaps

**POSITIVE -- paper §7.1 evaluation claims reproduce exactly.** Via
`paper/eval/README.md` commands:
- `h7_dtcm` -> reach-reject ("region `tx_buf` is in mem `dtcm`, which agent `eth`
  cannot reach"), at *target-load* time as the paper states.
- `nrf_flash` -> reach-reject (flash unreachable by `easydma`).
- `h7_cache` -> coherence-reject, and it prints the vendor-prescribed fix ("Mark
  mem `dma_pool` `cacheable = false`") -- backing the "rejects AND generates the
  fix" claim.
- `h7_fixed` -> builds through codegen.
Claims-vs-implementation for the evaluation section is verified.

**C1 (Low) -- paper DOI disagrees with all other metadata.** Paper masthead
(`region-ownership.tex:43`) cites `10.5281/zenodo.20878734`, while `CITATION.cff:23-24`
and `README.md:6,130` all cite `10.5281/zenodo.20878733` (one digit off). A reader
following the paper's own DOI reaches a different Zenodo record than the canonical
one. Fix: reconcile to the correct record id. Effort: S.

**C2 (Very Low) -- page-count claim inconsistent.** `paper/README.md:46` says the
PDF is "6 pages"; `paper/REVIEW.md:85` says "8 pages". Cosmetic. Effort: S.

**T1 (Medium) -- CI exercises neither the QEMU exec layer nor IKOS verify.**
`.github/workflows/ci.yml` installs only `llvm-18` -- no `qemu-system-arm`, no
`arm-none-eabi-*`, no IKOS. So `exec.rs` (behavioral correctness at `-O0`/`-O2`,
incl. the wrapping/volatile guards) and all `verify_*` tests **skip in CI**. The
two layers that substantiate the strongest claims -- "runs end-to-end under QEMU"
and formal discharge -- are unverified by CI; a regression in either passes green.
This is also why **S1** (a valid program `llc` rejects) and a `volatile`-elision
regression like **F2** could land without CI noticing. Fix: add qemu + arm-none-eabi
+ IKOS to a CI job (or a scheduled one). Effort: M.

**T2 (Low) -- `known_bug!` is defined but never used.** `bml/tests/exec.rs:205`
provides a mechanism to pin a known miscompile as an `#[ignore]`d reproducer;
there are 0 invocations. S1 and F2 have no pinned regression test. Fix: pin S1
(and F2 once a target is wired) via `known_bug!`. Effort: S.

**T3 (Low) -- coverage blind spots.** 15 V-codes are allowlisted in
`diagnostic_coverage.rs` as "no fixture yet" (the ratchet keeps them honest but
they are untested); `bml/src/main.rs` (1211-line CLI driver / pipeline
orchestration) has 0 unit tests. Neither is a soundness bug; both bound how much
the suite substantiates the safety story. Effort: M.
